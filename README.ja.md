# LoneFuzz

[English](README.md) | **日本語**

Android アプリの **exported コンポーネント**（他アプリから起動・呼び出しできる
Activity / Service / BroadcastReceiver / ContentProvider）に、入力検証漏れを突く
Intent を送り込み、**ローカル DoS（クラッシュ / ANR）** を再現可能な形で実証する、
**オンデバイス完結**のツールです。

PC やエミュレータ、root は不要。端末にサイドロードした APK 1 本で
「列挙 → 探索 → 検知 → 連射」までを完結させます。

> ## ⚠️
> - 検証対象は **自分が所有／管理する端末・アプリ**、または **書面で明示的に許可を得た対象** に限定してください。
> - 無許可の第三者への使用は法令違反となる場合があります。すべての責任は利用者にあります。

## 仕組み

### 1. Enumeration

端末にインストールされたアプリを走査し、他アプリから呼び出せる（exported な）
コンポーネントを列挙します。各コンポーネントの名前・種別と、アプリのバージョンを
端末上で直接取得するため、外部の静的解析は不要です。

Android 11 以降は他アプリの情報取得が制限されているため、列挙と明示起動のために
「全パッケージを参照する権限」を宣言しています（サイドロード時に自動付与）。

### 2. Payloads

未処理例外を誘発しやすい入力の「型」をまとめています。exported コンポーネントが
「呼び出し側は正しい入力（extras / data）を必ず付けてくる」と暗黙に仮定している箇所を突きます。

| レシピ | 送るもの | 誘発する例外・現象 |
|---|---|---|
| 空 Intent | extras 無しの素の Intent で発火 | NullPointerException（必須キーの取り出し結果にそのままアクセスしている箇所） |
| 型不一致 | 文字列を期待しがちなキーに文字列、数値を期待しがちなキーに配列を入れる | ClassCastException 等 |
| 巨大 int / 負値 | 共通キーに `Int.MIN_VALUE`、`count`/`size` に `Int.MAX_VALUE`、`length` に `-1` など極端な値を入れる | ArrayIndexOutOfBounds / サイズ計算の破綻 |
| TooLarge（既定オフ・重い） | `payload` キーに 2MB の byte 配列（Binder トランザクション上限 ≒1MB を超過） | TransactionTooLargeException |
| 不正 URI | `data` に存在しない content:// / file:// の URI を入れる | FileNotFoundException 等 |
| BadParcelable | 共通キー全てに、相手プロセスに存在しない自作 Parcelable を入れる（相手が extras を読み込んだ瞬間に発火） | BadParcelableException |
| FGS 5秒ルール | Service を extras 無しで `startForegroundService` 起動（Service のみ対象） | 5秒以内に `startForeground()` されず、約30秒後に `RemoteServiceException`（クラッシュダイアログは出ない） |

> 文字列／数値キーへの入れ替えは「どちらを読んでも型アンマッチになる」よう双方向に仕込みます。
> 共通キーは汎用 extras 名のリスト（id, url, uri, data, key, value, name, title, type,
> index, position, count, token, json, payload, extra, message）。
> BadParcelable は相手が extras を読むまで発火しないため、的中率は実装依存です。

発火方法はコンポーネント種別ごとに、Activity は `startActivity`、Receiver は
`sendBroadcast`、Service は `startService` / `startForegroundService`、
Provider は `ContentResolver` 経由の query を**隔離した `:probe` プロセス**から行います
（Provider が落ちると query した側のプロセスも道連れになるため、probe を犠牲にします）。

### 3. Detection

**どのコンポーネントの、どのペイロードで落ちたか**を特定する必要があります。クラッシュは
相手プロセスで非同期に起きるため、**発火記録と時間で対応付けた複数の信号**から、
クラッシュを誘発した「有効なペイロード」を判定します。

| 信号 | 仕組み | 対象コンポーネント | 主な弱点 |
|---|---|---|---|
| **クラッシュ/ANR ダイアログ観測** | ユーザー補助サービスがシステムの「停止しました」「応答していません」系ダイアログを観測し、直近 8 秒の発火記録と突き合わせる | 全種別（発火したものすべて） | 文言が OS・言語・メーカーで揺れる。「静かなクラッシュ」は捕捉できない |
| **即戻り（rapid return・最終手段）** | 対象 Activity が発火から 1.5 秒以内に消えて自アプリへ戻ったら、有効なペイロードの疑い | Activity のみ | 即 `finish()` する Activity や、権限要求ですぐ戻る Activity を誤検知する |
| **UsageStats 即消失観測** | 使用アクセスを用い、発火後に対象が前面に現れたのち、こちらの操作を介さず消えたことを履歴から確認 | Activity のみ（前面に出たもの）。1.5〜3 秒帯の「静かなクラッシュ」を捕捉 | 即 `finish()` と区別できない。履歴は数秒遅れて現れる。起動直後の死亡は記録が残らず不可 |
| **プロセス終了理由**（任意） | 発火後に OS の終了履歴を照会し、クラッシュ（`REASON_CRASH` / `REASON_CRASH_NATIVE` / `REASON_INITIALIZATION_FAILURE`）による終了を観測 | 全種別（発火したものすべて） | 他パッケージの照会に DUMP 権限が必要（初回のみ `adb` で付与）。API 30 以降 |

これらを統合し、検知結果に**信頼度**を付けます。クラッシュ死の観測（クラッシュ/ANR ダイアログ、
または任意の終了理由）を確定とし、即戻りと UsageStats 即消失は「ユーザー操作なしの消失」という
同じ曖昧さを共有するため、確定的な判定とは分けます。

誤検知を抑えるため、**下位の信号は上位が使えないときだけ**採用します。DUMP 付与時は終了理由が
真実なので、クラッシュ死が観測できない消失は疑いとして報告しません。使用アクセスがある場合は
UsageStats を優先し、どちらも無い場合に限り即戻りを使います。

| 信頼度 | 判定根拠 | 必要な権限 |
|---|---|---|
| **CONFIRMED** | 発火後に対象プロセスのクラッシュ死を観測（クラッシュ/ANR ダイアログ、または任意の終了理由） | ダイアログ: ユーザー補助（任意）/ 終了理由: DUMP（任意） |
| **SUSPECTED** | DUMP 未付与時のみ。使用アクセスがあれば「前景→説明のつかない即消失」、無ければ即戻り（最終手段） | UsageStats: 使用アクセス / 即戻り: 不要 |
| NONE | どの信号も無し（非該当） | — |

結果は「アプリ名 / バージョン / コンポーネント / レシピ / 信頼度」の形で出力できます。

Activity 以外は時間ベースで判定します。発火直後と少し後の2回、対象が発火以降に死んだかを
終了理由へ問い合わせます。バックグラウンドの相手への `startService` は Android に拒否される
（`BackgroundServiceStartNotAllowedException`）ため、`bindService` で対象を起こしてから
再試行します。FGS 違反は約30秒後にクラッシュとして現れるので、このレシピだけ31秒待ちます。
Provider は**プロセスの死**だけを確定とし、呼び出し側に返る例外は正常な拒否として扱います。

### 4. Burst

探索で確定した有効なペイロードだけを繰り返し送り続け、対象を落とし続けます。
フォアグラウンドサービスとして常駐通知付きで持続実行します。停止は常駐通知から行います。

### 武器庫（有効なペイロードの永続化・再適応）

確定した有効なペイロード（CONFIRMED）は「パッケージ / コンポーネント / レシピ」をキーに端末内へ保存され、
再起動後も **探索（spray）を省いて、そのまま落とし続けるモードで使えます**。疑い（SUSPECTED）は
誤検知を含みうるため保存しません。対象をアンインストールすると自動で削除されます。

自己適応は **「バージョン番号」ではなく「効いたかどうか（効果）」** で駆動します。
以前は効いていたペイロードが、落とし続けるモードの実行中に連続で効かなくなると（＝仕様変更で無効になった可能性）、
そのペイロードを武器庫から無効化してログに残します（連射は止めません。再探索は手動の spray で行います）。
バージョンは「最後に有効と確認した版」として記録するだけで、無効化の判断には使いません。

## 権限モデル

**攻撃（Intent の発火）そのものに権限付与は不要**です。権限は「検知の確度」と
「自動化」のために使います。

- **全パッケージ参照**: 他アプリのコンポーネント列挙と明示起動に必要（サイドロード時に自動付与）。
- **ユーザー補助（Accessibility）**: クラッシュ/ANR ダイアログの検知と自動巡回に使用（任意。無くても手動で目視確認できます）。
- **使用アクセス**: 静かなクラッシュを補足する補助信号（任意）。
- **フォアグラウンドサービス / 通知**: 落とし続けるモード（持続実行）と常駐通知に使用。
- **バックグラウンドプロセスの終了 / タスク順序**: 後始末・巡回の補助。
- **DUMP**（adb で付与）: 対象プロセスの終了理由を照会し、クラッシュ死をダイアログ非依存で確定（任意）。

## 操作モード

| モード | 用途 | 権限 |
|---|---|---|
| **SHOT（単発）** | 選択対象を検知待ちなしで1周だけ高速に撃つ（目視確認用） | ゼロ権限 |
| **SPRAY（探索）** | 選択した対象アプリの exported Activity × レシピを1つずつ巡回し、各発射後にクラッシュ/ANRを待って検知・記録（時間がかかる。対象選択は必須） | ユーザー補助（自動化/検知） |
| **BURST** | 確定した有効なペイロードだけをループで送り続け、対象を落とし続ける（武器庫から spray 無しで再利用可） | ユーザー補助 + フォアグラウンドサービス |

## ビルド & 実行

1. Android Studio でプロジェクトを開く（AGP 9.3.3 / Gradle 9.5 / compileSdk 37 / minSdk 24）。
2. 実機にサイドロードする（`Run` または `adb install`）。
3. 初回起動で列挙が走る。対象アプリとレシピを選んで発火します。
4. 全自動の探索／落とし続けるモードを使う場合は「設定 → ユーザー補助 → LoneFuzz」を有効化（任意）。
5. 検知を確定まで強化する場合は DUMP を付与（任意。初回クラッシュも確定できます）:
   `adb shell pm grant io.github.azaberrypi.lonefuzz android.permission.DUMP`
   未付与のときはアプリの画面に赤いピルで表示されます。

> 補足: デバッグ時は `adb logcat` を併用すると確定が容易です。

## 既知の制約

- クラッシュは相手プロセスで非同期に起きるため、こちら側の呼び出しは通常は例外を投げません。
  ログの「送信成功」は「落とした」を意味しません（落ちたかどうかは上記の検知が判定します）。
- Android 12 以降はクラッシュ通知がレート制限され、ダイアログ観測だけでは確定を取り損ねます。
  DUMP 付与時の終了理由照会がこれを補い、初回クラッシュや静かなクラッシュも確定できます。
- Activity の持続的な連射は、Android のバックグラウンド起動制限の影響を受けます。
- BadParcelable は相手が extras を読むまで発火しません（的中率は実装依存）。
- Service / Receiver / Provider に対応しましたが、Activity 以外の確定には終了理由（DUMP）またはクラッシュダイアログが必要です。呼び出し側に例外を返すだけの Provider は HIT にしません。
